## 2. 재개 절차

```bash
# 사전 요구: Node 22+, JDK 17

# 0) AI 키 (없으면 스텁 모드로 동작 — 데모는 여전히 가능합니다)

#    BE/.env 에서 AI_PROVIDER=openai / OPENAI_API_KEY=sk-... 설정

# 1) 백엔드 — http://localhost:8080
cd BE && ./gradlew bootRun

# 2) 프론트엔드 — http://localhost:5173 (다른 터미널)
cd FE && npm install && npm run api:types && npm run dev
```

### ⓪ 무대 영상 URL 13개 교체 ★남은 유일한 구멍

`BE/src/main/resources/data.sql` 의 `artist_stage` 13행이 **전부 같은 영상**을 가리킵니다
(`d4pWjMsd0go` — 임베드 검증이 끝난 유일한 ID 라 우선 넣었습니다). 그래서 지금은
"이찬원 무대 보여줘" 에 박서진 영상이 나옵니다. 구조와 흐름은 완성돼 있고 URL 만 채우면 됩니다.

⚠️ 교체 시 **반드시 iframe 안에서** 재생을 확인하세요 — 주소창에 embed URL 을 직접 여는
검증은 무의미합니다 (정상 영상도 오류 153).

### ⓪-1 음성 발화 인식률 확인

**음성 입력은 Claude 가 검증할 수 없습니다.** 액션 판정 어휘(`IMPERATIVES`)는 텍스트로는
전부 통과했지만, STT 가 조사·띄어쓰기를 어떻게 끊느냐에 따라 빗나갈 수 있습니다.
**직접 말해보고 안 걸리는 표현을 알려주시면** 목록에 더하면 됩니다
(`BE/.../VoiceActionResolver.java` + `FE/.../voiceCommands.ts` **양쪽**).
자세한 내용은 `docs/worklog-fe.md` §1-1.

## 8. 이 환경의 함정 (다시 밟지 말 것)

| 함정 | 대응 |
|---|---|
| **`cmd \| tail` 은 종료 코드를 가립니다** | 빌드/테스트는 `; echo EXIT=${PIPESTATUS[0]}` 로 확인. 이것 때문에 실패를 성공으로 두 번 오판했습니다 |
| **경로에 한글·공백** (`바탕 화면`) | `gradle.properties` 의 `org.gradle.jvmargs` 에 `-Dfile.encoding` 금지 → 테스트 워커 `ClassNotFoundException` |
| **Git Bash 가 한글을 CP949 로 전송** | 요청 본문·**쿼리 파라미터·heredoc 전부** 해당. 한글 본문은 파일로 저장 후 `--data-binary @file`, 쿼리는 `python -c "urllib.parse.quote(...)"` 로 직접 인코딩 |
| **`bootRun` 로그의 한글이 깨져 grep 이 안 됩니다** | ASCII 패턴(`provider=`, `AiAnalysisWarmup`)으로 grep 하세요 |
| **재기동 시 포트 8080 충돌** | gradle 래퍼를 죽여도 forked JVM 이 남습니다. `netstat -ano \| grep :8080` → `taskkill //PID <pid> //F` |
| **AI 언어 지시는 목표 언어로 써야 합니다** | 한국어 프롬프트에 "English 로 답하세요"라고 쓰면 모델이 한국어로 답합니다 (실제로 겪음) |
| **Spring Boot 4 = Jackson 3** (`tools.jackson`) | Jackson 2 기준 설정 프로퍼티는 바인딩 실패 |
| **Spring Boot 4 스타터명** | `spring-boot-starter-web` → `spring-boot-starter-webmvc` |
| **`data.sql` 이 DDL 보다 먼저 실행** | `spring.jpa.defer-datasource-initialization: true` 필수 |
| **TS 6 + `erasableSyntaxOnly`** | 생성자 파라미터 프로퍼티·`enum` 사용 불가 |
| **`openapi-typescript` 가 TS 6 과 peer 충돌** | devDependency 대신 `npx` (`npm run api:types` 에 반영됨) |
| **`<button>` 은 내용 폭으로 줄어듭니다** | `<label>` 을 버튼으로 바꿀 때 `width: 100%` 를 잊으면 폭이 줄어듭니다 (실제로 겪음) |
| **Vite 가 낡은 모듈을 계속 서빙합니다** | `does not provide an export named 'default'` 인데 `npm run build` 는 EXIT=0 이면 HMR 캐시입니다. 새로고침이 아니라 **`rm -rf node_modules/.vite` + dev 서버 재시작** |
| **YouTube 임베드 차단 영상은 조용히 실패** | 검은 화면 + 스피너만 뜹니다. 영상 교체 시 임베드 가능 여부 확인 필수. **주소창에 `youtube.com/embed/...` 를 직접 여는 검증은 무의미** — 최상위 탐색이면 정상 영상도 `오류 153` |
| **`YT.Player` 는 마운트 엘리먼트를 iframe 으로 치환** | 클래스 붙은 div 를 직접 넘기면 스타일이 통째로 날아갑니다. 안에 버릴 div 를 만들어 넘기세요 |
| **`.env` 의 `KEY=` (빈 값)는 `${KEY:기본값}` 을 무력화합니다** | 환경변수가 **존재하되 비어 있으면** 기본값이 아니라 빈 문자열이 주입됩니다. `AUTH_SECRET` 이 이래서 로그인이 전부 500 이었습니다. 시크릿을 읽는 쪽에서 `isBlank()` 를 한 번 더 거르세요 |
| **모임 상태값은 `OPEN` 이 아니라 `RECRUITING`** | 스크립트로 신청 가능한 모임을 고를 때 `OPEN` 으로 찾으면 0건이 나옵니다 (`RECRUITING`/`FULL`/`CLOSED`) |
| **SSE 스트리밍 스레드에는 로그인 정보가 없습니다** | `SecurityContextHolder` 는 ThreadLocal 입니다. 요청 스레드(컨트롤러)에서 `userId` 를 읽어 넘기지 않으면 음성 응모·신청이 **항상 비로그인**으로 보입니다 |
| **트랜잭션 안에서 쓰기 예외를 잡으면 전체가 롤백됩니다** | 참여 서비스가 던진 `ApiException` 을 잡아도 공용 트랜잭션이 rollback-only 로 마킹됩니다. `ChatService.ask` 를 `Propagation.NOT_SUPPORTED` 로 둔 이유입니다 |
| **YAML `description` 에 `키: 값` 을 그냥 쓰면 파싱이 깨집니다** | `description: 비로그인이면 \`entered: false\`...` 가 매핑으로 해석돼 `npm run api:types` 가 실패합니다. 따옴표로 감싸세요 |
| **`clearAutomatically = true` 벌크 UPDATE 앞에서 읽은 엔티티는 준영속입니다** | 그 뒤에 수정해도 **UPDATE 가 안 나갑니다.** 모집 신청이 이래서 `CANCELED` 로 남아 한 사람이 무한히 재신청할 수 있었습니다 (`worklog-be.md` §1-3). 벌크 연산 뒤에는 **다시 조회**하세요 |
| **바텀시트 `max-height` 는 내용이 길어질 수 있는 화면에서 위험합니다** | 음성 답변 + 영상 + 버튼이 70vh 를 넘어 **화면 밖으로 잘렸습니다.** 시트는 마스코트 때문에 `overflow` 를 자를 수 없어서, **안쪽 답변 영역만** 스크롤시킵니다 |
| **넘치는 flex 컨테이너에 `justify-content: center` 를 쓰지 마세요** | 내용이 길면 **위쪽이 잘려 스크롤로도 못 돌아갑니다.** 자식에 `margin: auto 0` 을 쓰세요 |
| **경로 리터럴은 `{id}` 보다 위에 선언해야 합니다** | `/gatherings/mine` 을 `/gatherings/{id}` 아래 두면 `mine` 이 id 로 해석됩니다 |
| **`useEffect` 안에서 `mutate()` 를 부르면 StrictMode 에서 상태가 `pending` 에 갇힙니다** | 요청은 201 로 끝나고 `onSuccess` 도 실행되는데 **`isSuccess` 가 영원히 false** 입니다. 결과를 `useState` 로 따로 받으세요 — 닉네임 룰렛이 이래서 "추첨 중…" 에 멈춰 **앱에 못 들어갔습니다** |
| **백그라운드 탭은 타이머가 초당 1회로 스로틀링됩니다** | 60~320ms 로 스케줄한 룰렛이 브라우저 자동화(비활성 탭)에서는 10배 넘게 느려집니다. **멈춘 것으로 오진하기 쉽습니다** — 실제 사용(포그라운드)에서는 설계대로 ~2.4초 |
| **음성 액션이 엉뚱한 대상을 잡으면 프롬프트가 아니라 코드를 보세요** | 액션 경로는 **LLM 을 호출하지 않습니다.** 대상 선택은 `VoiceActionResolver` 의 결정적 키워드 매칭입니다 |
| **한국어 불용어는 어간으로 걸러야 합니다** | "응모" 만 불용어에 넣으면 **"응모해"·"응모하고"** 가 이름 단서로 남아 어느 대상과도 안 맞습니다. `REQUEST_STEMS` 로 `startsWith` 검사하세요 |
| **기능을 추가하면 `ServiceCatalog` 설명도 고치세요** | 근거에 없으면 도우미가 **"이 앱에서는 할 수 없다"** 고 단정합니다. 응모 취소가 되는데도 못 한다고 답했습니다 |
